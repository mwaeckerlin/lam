# Features

Numbered register of every feature; a number is never reused. Every feature is covered by tests listed in [TESTS.md](TESTS.md); the guard `tests/docs-contract.sh` fails when a feature has no test. F1, F4, F5 and F8 were found in the old image and are kept; the others came with the rebuild on the headless base images.

- **F1 — LDAP Account Manager at the root path.** The administrator opens the address of the web container and manages the users and groups of his LDAP directory with the current LAM release. The start page carries the title «LDAP Account Manager» and leads to the login page; the login page offers the administrator of the server profile, and a login with the LDAP password opens LAM, a wrong password shows the login page again. Every PHP module LAM needs is present, so the login page reports no missing extension.
- **F2 — First start configured from the environment.** On the first start on an empty volume, the administrator gets a working main configuration and server profile without opening a configuration page: the LDAP server, the base of the directory (derived from the domain unless given), where users and groups are kept, the administrator offered at the login, the language, the storage of the configuration (files or a MySQL database) and the configuration password come from the variables named in the README, with the defaults of the official LAM image. The password is stored only as a salted hash; passwords and the administrator can also come from files (Docker secrets). With `LAM_SKIP_PRECONFIGURE=true` nothing is written.
- **F3 — No configuration without a password.** Without a configuration password on the first start, and with an invalid value of a variable, every LAM page answers with status 503 and a message that says what the administrator has to set; the start page is still served. An unwritable volume answers 503 with the message that the volume has to be made writable.
- **F4 — Persistent configuration in the volumes of the old image.** The main configuration lives in `/etc/ldap-account-manager`, the server profiles, PDF structures, account profiles, sessions and temporary files in `/var/lib/ldap-account-manager`, with the layout of the old image; an existing configuration is used as it is and never overwritten by the variables.
- **F5 — Defaults restored into the volumes.** On every start, every file of the LAM release that is missing in the data volume is copied into it, and no existing file is overwritten; an empty volume works also where Docker does not fill it, as in Docker Swarm.
- **F6 — Internal files never served.** The configuration, the sessions, the temporary files, the PHP libraries, the help texts and the translations answer 404 from the web container; PHP sources are executed, never delivered; an unknown address answers 404.
- **F7 — Headless images, never root.** Both images contain no shell, no busybox and no perl, and run as an unprivileged user.
- **F8 — Health check.** The PHP container reports itself healthy while PHP accepts requests, checked every 60 seconds after a start period of 600 seconds.
- **F9 — Published for amd64 and arm64.** Every push builds both images natively for both architectures and publishes them on Docker Hub as `mwaeckerlin/lam:php-fpm` and `mwaeckerlin/lam:nginx`, with the reusable workflow of `mwaeckerlin/scratch`, and again every week for the security fixes of the base images.
